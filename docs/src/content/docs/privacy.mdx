The Systematic docs site is designed to respect your privacy. This page documents exactly what is and is not collected when you visit.

## Analytics

The docs site uses [Umami](https://umami.is/), a self-hosted, open-source analytics platform deployed at `metrics.fro.bot`. No third-party analytics provider processes your data.

Analytics are **only active** when the site is built with the `UMAMI_WEBSITE_ID` environment variable set. In development builds this variable is unset, so no tracking script is loaded at all.

### What is collected

- **Aggregate pageviews** — which pages are visited and how often, with no visitor-level linkage across sessions.
- **One named interaction event:** `click_install_cta` — recorded when a visitor clicks an install call-to-action.
- Quick Start page visits are captured as ordinary aggregate pageviews, not as a separate named event.

That is the complete list. Nothing else is collected.

### What is not collected

- **No cookies.** Umami operates without setting any cookies.
- **No personally identifiable information (PII).** Names, email addresses, and device identifiers are never recorded.
- **No cross-site tracking.** The tracker is self-hosted and does not participate in any ad network or cross-domain tracking scheme.
- **No fingerprinting.** Canvas, font, or hardware fingerprinting is not used.
- **No URL query strings or fragments.** The tracker is configured with `data-exclude-search="true"` and `data-exclude-hash="true"`, so query parameters and URL fragments are stripped before any pageview is recorded.

### Do Not Track

The tracker is configured with `data-do-not-track="true"`. Umami honors the browser [Do Not Track](https://www.eff.org/issues/do-not-track) signal — when DNT is enabled in your browser, no data is sent.

### Self-hosted, no third-party processor

All analytics data stays on infrastructure controlled by this project. No data is shared with, sold to, or processed by any third party.

### IP addresses and identifiers

No raw IP addresses or personal identifiers are stored. Visitors are counted using a one-way hash that rotates monthly, so the same visitor cannot be tracked across months and the original IP cannot be recovered. Approximate location (country, region, city) is derived locally from the IP address at collection time, with no third-party calls. Visitors with Do Not Track enabled are not recorded at all.

## Plugin runtime

The Systematic plugin itself — the code that runs inside your harness on your machine — **transmits no telemetry of any kind**. It does not phone home and does not report usage. In the default setup it makes no network call at all. Analytics are strictly limited to this documentation website.

There is one optional exception, and it is off until you turn it on.

### Optional embeddings endpoint for search

[Search](/systematic/guides/search/) can add a semantic lane. You turn it on by setting `search.embeddings` in your user-level config. Once you do, Systematic sends text to the endpoint you named:

- **Document text.** `systematic search --warm` sends the text of your `docs/solutions` documents to the endpoint, in chunks of at most about 1,200 characters. Each chunk starts with the document title and its heading path. The first chunk of each document holds its title, symptoms, tags, module and `applies_when` fields.
- **Queries.** Each search sends the query text to the endpoint, but only when the index is complete. While the index is incomplete, a search sends nothing.

The endpoint can be any host you name in `base_url`. A host on your own machine, such as Ollama, keeps the text on that machine. A remote host is a third party. It receives your document text and your queries, and its own privacy terms apply. Systematic does not restrict the host, and it does not refuse `http://` for a remote host. Use `https://` for any host that is not on your machine.

Systematic itself adds no telemetry here. It sends nothing to Systematic's maintainers and nothing to any host you did not name. Only your user-level config can set the endpoint. A project config cannot, so a repository you clone cannot redirect your documents to a host of its choosing.

**The API key.** `api_key_env` holds the name of an environment variable, never the key. Systematic reads the variable when it makes a request and sends the value as a bearer token to the endpoint you named. It never logs the key, never writes it to a file, and never prints it or the variable name in an error.

**The local cache.** Embedding vectors are cached on your machine so a search does not re-embed unchanged documents. The cache is the directory `$XDG_CACHE_HOME/systematic/embeddings/` when `XDG_CACHE_HOME` is an absolute path, and `~/.cache/systematic/embeddings/` otherwise. The directory is created with mode `0700`, and every file in it is written with mode `0600`. The files hold vectors and small failure markers. They hold no document text and no query text, but a vector is derived from the text it came from. To delete everything Systematic cached, delete that directory. Systematic removes entries it has not read for 30 days.

The [search guide](/systematic/guides/search/) lists every setting and shows how to switch the whole feature off.

### Bootstrap text on OpenCode v2

On OpenCode v2, the plugin hands its bootstrap text to OpenCode, which stores it as an instruction entry in OpenCode's own local session database. The plugin itself sends nothing off your machine; the text reaches your model provider as part of each request, as the bootstrap always has. The entry is part of the session's stored state, and it stays there after you remove the plugin. If you point `bootstrap.file` at a file that holds sensitive text, that text is stored the same way, so keep sensitive text out of that file.
