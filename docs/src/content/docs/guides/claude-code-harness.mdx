Systematic ships a self-contained Claude Code plugin, built and identifier-translated in CI from the same skills and agents that power the OpenCode and Pi integrations. The plugin is never committed to `main` — it's built fresh on every push and published to a dedicated `claude-code-plugin` branch — and it targets Claude Desktop's embedded Claude Code (the Code tab) and Cowork.

## Install

The plugin is distributed through the Claude Code plugin marketplace flow, using the marketplace catalog checked into this repository at `.claude-plugin/marketplace.json`:

```
claude plugin marketplace add marcusrbrown/systematic
claude plugin install systematic@systematic
```

The catalog points the `systematic` plugin entry at the `claude-code-plugin` branch, so `claude plugin install` always pulls the latest published build. There's no manual version to bump — the plugin has no version field and is versioned by the source commit SHA baked into each publish.

Installing the plugin does not require or touch an existing OpenCode or Pi setup in the same project — the three integrations are independent.

## What you get

Once installed and enabled, the plugin registers:

- **Bundled skills as native Claude Code skills** — every skill is copied and identifier-translated from the source `skills/` directory into a `SKILL.md` (with subfiles), so Claude Code's own Skill tool discovers and invokes them the same way it would any other skill. Invoke them as `systematic:<skill-name>`.
- **Bundled agent personas as native subagents** — persona files are flattened from `agents/` into one Markdown file per agent and dispatched by name in a prompt (for example, "Use the systematic-implementer subagent to implement the auth module"), addressed as `systematic:<agent-name>`.
- **Behavioral enforcement via a plugin output style** — a generated output style composes the using-systematic discipline (invoke skills before responding, plan before multi-step changes) with the Claude Code capability profile. Output styles with `force-for-plugin: true` modify the system prompt directly and auto-apply as soon as the plugin is enabled — this is the mechanism that makes enforcement install-alone rather than something you have to separately configure.
- **Declarative session state via a `SessionStart` hook** — a generated hook runs a static command that reports declarative facts into session context: how many skills and subagents are available, and where enforcement lives. This hook carries state only; it does not attempt to inject behavioral instructions, because imperative hook content is treated as prompt injection and refused.

Every identifier in the bundle — skill references, agent references — is rewritten at build time from Systematic's internal source form (`ce:<name>`, `systematic:<category>:<name>`) to Claude Code's plugin-namespaced form (`systematic:<skill-dir>`, `systematic:<agent-stem>`). A build-time integrity check fails the build if any source-namespace form or unresolved reference leaks into the published bundle, so what installs is guaranteed self-consistent.

## The layered model

Systematic's Claude Code integration is deliberately layered rather than relying on one mechanism to do everything:

| Layer | Mechanism | Role |
|---|---|---|
| Enforcement | Plugin output style (`force-for-plugin: true`) | Authoritative, install-alone behavioral discipline |
| State | `SessionStart` hook | Declarative session facts (skill/subagent availability) only |
| Workflow | Native skills | Skill content and instructions, discovered natively |
| Agents | Native subagents | Persona dispatch by name |

## Honest capability boundary

Output-style enforcement is real and applies automatically on install, but it operates at the system-prompt level, the same layer as any other instruction the model receives — it is strong guidance, not a hard gate the model cannot violate. Treat it the way you would treat any other system-prompt-level policy: reliable in practice, not cryptographically enforced.

Coverage also differs by surface. Plugin-bundled hooks fire app-wide, including in Cowork. A project-local `.claude/settings.json` hook, by contrast, fires in the Code tab but not in Cowork — if you need state or enforcement to reach Cowork sessions, it has to come through the plugin, not a project-local hook.

Systematic ships no `systematic_skill` tool on Claude Code, unlike its OpenCode and Pi adapters. Skill invocation goes entirely through Claude Code's own native Skill tool and `SKILL.md` discovery — there is no Systematic-specific resolution layer to reason about on this harness.

## Uninstall

Disable or remove the plugin from Cowork → Customize → Plugins (or the equivalent Code tab surface). No project files are modified by installation, so there is nothing else to revert.
